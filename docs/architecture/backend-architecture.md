Start with [named features](../README.md#feature-lookup), [API setup](../../apps/api/README.md), [API instructions](../../apps/api/AGENTS.md) and the [authoritative Java style/architecture skill](../../.agents/skills/backend/SKILL.md). ## Responsible layers

Controllers bind HTTP/method security; services own rules/transactions; repositories/queries and DTO/mappers own persistence/projections. App instructions/skill own conventions and actual module structure; do not infer required interfaces or modules from old diagrams. Preserve `/api/v1`, boundary validation, ownership/version concurrency and public/private DTO separation. The [V1 fresh-install baseline](../../apps/api/src/main/resources/db/migration/V1__baseline.sql) consolidates the explicitly authorized unapplied V1–V24 history; subsequent applied migrations are append-only; [runbook](../deployment/README.md) owns backup/restore and release safety.

## Auth and private data

[Authentication](authentication.md), [Recognition](recognition.md), [avatar crop](../ui/owners/identity-and-recognition.md#avatar-crop-and-storage-contract) and [rooms](study-rooms.md) retain active domain contracts. A public profile, generic storage URL or shared UI never grants access to private bytes. Avoid logging credentials, tokens or evidence contents; keep Hibernate JDBC bind diagnostics off for private `bytea` data.

## Questions and exams

- [QuestionServiceImpl](../../apps/api/src/main/java/me/nghlong3004/olympic/question/service/impl/QuestionServiceImpl.java) and its validation/figure owners enforce scientific `schemaVersion:1` content, not HTML/remote figures. Staff edits require owner/admin eligibility and `expectedVersion`.
- [API data invariants](../../apps/api/AGENTS.md#security--data-invariants) own manual-figure types/size/count/pixel limits. Private figures live in PostgreSQL, not Cloudinary; staff reads are `no-store`, and import validation is separate.
- [ExamServiceImpl](../../apps/api/src/main/java/me/nghlong3004/olympic/exam/service/impl/ExamServiceImpl.java) delegates drafts, [publication](../../apps/api/src/main/java/me/nghlong3004/olympic/exam/service/impl/ExamPublication.java), [reads](../../apps/api/src/main/java/me/nghlong3004/olympic/exam/service/impl/ExamPaperReads.java) and projections. Published paper/items/figures remain frozen. Student release is server-Clock-authoritative and excludes answers, explanations and solution-only figures, even when a client requests solutions. No attempt/grading workflow is implemented.
- Publication locks the exam, then ordered question rows and their ordered figure IDs through [QuestionFigureRepository](../../apps/api/src/main/java/me/nghlong3004/olympic/question/repository/QuestionFigureRepository.java). Its native `FOR UPDATE` scalar query uses the caller's JPA transaction without preloading bytes; the exam stays clean until frozen children have flushed. [ExamVerticalIntegrationTest](../../apps/api/src/test/java/me/nghlong3004/olympic/exam/ExamVerticalIntegrationTest.java) covers question/figure contention, byte snapshots and publication rollback.

## Import lifecycle

[AssessmentImportServiceImpl](../../apps/api/src/main/java/me/nghlong3004/olympic/assessment/service/impl/AssessmentImportServiceImpl.java), [RedisAssessmentImportQueue](../../apps/api/src/main/java/me/nghlong3004/olympic/assessment/service/impl/RedisAssessmentImportQueue.java), [processor](../../apps/api/src/main/java/me/nghlong3004/olympic/assessment/service/impl/AssessmentImportProcessorImpl.java) and [publication](../../apps/api/src/main/java/me/nghlong3004/olympic/assessment/service/impl/AssessmentPublicationServiceImpl.java) own the coordinated lifecycle:

- Redis wakeups happen after commit; committed QUEUED rows have bounded DB reconciliation, and pending deliveries recover. Terminal/review/published replay does no provider work.
- Locked QUEUED claims increment `attemptCount`. Phase/page/final/failure writes require the current status, attempt and unexpired lease. Expired processing becomes FAILED for explicit retry; do not automatically replay paid/provider work.
- Provider/PDF/upload work stays outside short DB transactions. Progress commits independently. Retry replaces unpublished children in FK-safe order; source bytes remain, and replaced generated bytes are removed only after the replacement commits.
- Known rollback/pretransaction failures compensate new uploads; uncertain commit retains potentially referenced bytes. Fencing prevents stale writes but cannot cancel an already-running external request.

## Upload compensation

[StorageUploadServiceImpl](../../apps/api/src/main/java/me/nghlong3004/olympic/storage/service/impl/StorageUploadServiceImpl.java) owns upload/persistence orchestration behind the existing storage endpoint. [StorageCompensation](../../apps/api/src/main/java/me/nghlong3004/olympic/storage/service/StorageCompensation.java) preserves original failures, compensates known rollback and does not delete committed files after an afterCommit exception. Crash before compensation registration, provider-delete failure and unknown commit can leave orphan bytes; no unsafe deletion is a substitute for reconciliation. This repair did not settle broader folder/media access policy.
