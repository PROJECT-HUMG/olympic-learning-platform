# Identity, profiles and Recognition UI

[Recognition policy](../../architecture/recognition.md) owns points/consent/eligibility/evidence; [named features](../../README.md#profile) link actual routes and tests. No public UI may substitute a private account DTO or invent activity/award metrics.

## Individual member profile and own achievements

`/users/:userId` and legacy `/achievements/:userId` share [AchievementProfilePage](../../../apps/web/src/features/recognition/public-pages.tsx). [Individual CSS](../../../apps/web/src/features/recognition/individual-recognition.css) owns a bounded reading column: avatar/full name/username, “Có {n} thành tích”, “Tổng {n} điểm”, then dated “Thành tích và giải thưởng”. Actual allowed records/count and `publicPoints` come from [RecognitionServiceImpl.profile](../../../apps/api/src/main/java/me/nghlong3004/olympic/recognition/service/impl/RecognitionServiceImpl.java); they are neither ranking totals nor number of prizes. `award=NONE` remains “Chỉ tham gia”; [presentation model](../../../apps/web/src/features/recognition/achievement-presentation-model.ts) owns actual labels/breakdowns.

[UserIdentity](../../../apps/web/src/features/user/components/user-hover-card.tsx) keeps a real profile anchor with optional pointer/focus preview; keyboard Enter/touch work without hover. [Profile query](../../../apps/web/src/features/user/hooks/use-public-profile.ts) revalidates and masks cached summaries during refetch/error. [Return helper](../../../apps/web/src/features/user/lib/public-identity.ts) accepts only known same-origin entry paths and preserves query/hash, with deterministic fallback. Historical/unavailable identities remain honest unlinked attribution.

[MyAchievementsPage](../../../apps/web/src/features/recognition/private-pages.tsx) stays student management: actual history first, “Gửi thành tích”, “Xem hồ sơ của tôi”, optional visibility/ranking settings. The public page offers management only to its current student owner. `/profile` is separate private account/security editing. No private evidence, review notes or email is added to a public profile.

## Avatar delivery

[UserAvatar](../../../apps/web/src/features/user/components/user-avatar.tsx) / [AvatarImage](../../../apps/web/src/features/user/components/avatar-image.tsx) consume supplied `avatarUrl`/`avatarCrop`; initials handle missing/failed images. The crop/storage contract below applies to every supplied avatar.

Recognition list/detail/rankings batch participant identities through UserService; Documents/News enrich public author projections through their service/mappers. Lists render supplied images without one profile fetch per avatar. Optional profile summary loads only when preview opens. Public image delivery is separate from private evidence access; unavailable identities suppress profile/avatar disclosure as required.

### Avatar crop and storage contract

[UserServiceImpl](../../../apps/api/src/main/java/me/nghlong3004/olympic/user/service/impl/UserServiceImpl.java), [crop request](../../../apps/api/src/main/java/me/nghlong3004/olympic/user/request/UpdateAvatarCropRequest.java), [avatar-crop geometry](../../../apps/web/src/features/user/lib/avatar-crop.ts) and UserAvatar own the contract. `PUT /users/me/avatar` sends the original JPG/PNG/WebP (max5MB) plus optional JSON crop; `PATCH /users/me/avatar/crop` changes metadata only, without storage upload/delete; DELETE clears both. All act only on the current authenticated account.

Finite crop x/y are fractional alignment of overflow (0–1), zoom1–3 above cover, not source pixel coordinates. Use object-position/transform-origin from x/y and scale(zoom); the editor's inverse conversion must reopen the same selected region. Null/missing crop means centered cover/zoom1. The V1 baseline includes nullable crop columns and constraints; no image recrop/backfill or new cropped asset. Keep the applied migration on rollback. Successful save invalidates current identity/consumer caches; cancel/failure preserves the saved image. [Crop unit](../../../apps/web/tests/avatar-crop.test.ts) and [API integration](../../../apps/api/src/test/java/me/nghlong3004/olympic/user/AvatarCropIntegrationTest.java) checks cover geometry/ownership; cross-origin originals need no canvas download for metadata-only edits.

## Ranking interaction lookup

[RankingsPage](../../../apps/web/src/features/recognition/public-pages.tsx), [RankingList/Row](../../../apps/web/src/features/recognition/ranking-presentation.tsx) and [CSS](../../../apps/web/src/features/recognition/ranking-presentation.css) render one bordered, square-cornered horizontal card per member inside a distinct neutral content panel. Rank, wrapping profile name and points remain aligned; approved-record counts are retained in the API but omitted from these cards; tiny screens omit the redundant avatar. No name chevrons or hover-only navigation. Native all-time/year controls and a secondary scoring disclosure preserve readable hierarchy. Ranking points may exceed the linked profile's visible-only `publicPoints`.

Preserve the server's unique sequential ranks/order; [the contract](../../architecture/recognition.md#ranking-order-and-score-change-history) owns latest attainment and unknown legacy fallback. `scoreTimingKnown=false` shows “Chưa có mốc điểm cũ”; absent flags remain backward compatible. [Presentation model](../../../apps/web/src/features/recognition/ranking-presentation-model.ts) colors names using actual points: below20 neutral,20–49 blue,50+ teal, with legible light/dark colors. These are visual bands, not additional awards or a scoring rule. No keyword API or client re-ranking is added.

## Honors albums and attribution

`/honors` uses [HonorAlbumCard](../../../apps/web/src/features/recognition/honor-album-card.tsx) inside a distinct neutral panel. Each bordered card has its own card surface and equal media/title/attribution/action regions. Titles show up to three visual lines with the full accessible link name and full heading on detail; metadata and up to two attributed people are bounded teasers, with an actual remaining count. Missing images keep “Album chưa có ảnh” in the same cover region so cards/actions align. Image failure offers retry. Accent stays on navigation and “Xem album”; page/panel/card surfaces carry the visual hierarchy.

Attribution reuses Participants/UserIdentity without trailing chevrons. Available identities open the existing member profile; historical/unavailable identities remain honest unlinked text. Teasers do not assert scored awards; the detail keeps the full roster/editorial award text.

[HonorDetailPage](../../../apps/web/src/features/recognition/public-pages.tsx) has one back-arrow “Quay lại” action retaining the list URL context, followed by title → gallery → description → people in the shared panel. It has no local Rankings navigation. [HonorGallery](../../../apps/web/src/features/recognition/honor-gallery.tsx) keeps source order, arrow/touch controls, full-image dialog, Escape/focus return and reduced motion; filenames are not editorial captions. [Recognition CSS](../../../apps/web/src/features/recognition/recognition.css) owns two desktop columns/one mobile column. List cross-navigation carries only a valid calendar year; list/profile/album returns retain their supported URL context. Albums remain published memories, never achievements or a points source.

## Selecting and submitting Recognition evidence

[AchievementEditor](../../../apps/web/src/features/recognition/achievement-editor.tsx) uses controlled [Kokonut FileUploadSelection](../../../apps/web/src/components/kokonutui/file-upload.tsx). The drop zone, local raster thumbnails and file rows adapt official `@kokonutui/file-upload`2.0.0 from [the registry](https://kokonutui.com/r/file-upload.json), using installed Framer Motion. Actual File objects remain in the editor; [validation](../../../apps/web/src/features/recognition/validation.ts) owns MIME/count/size. Invalid additions retain selection. Native chooser keyboard/drop/file-paste/add/remove, wrapped names and busy/dirty/focus contracts share this path. Raster previews use owned blob URLs, revoked on removal/unmount; unsupported/broken images and PDFs remain file badges, with no claimed PDF thumbnail. Selection rows say “Đã chọn”, not “Đã tải lên”. Upstream simulated uploads/failures are excluded. The separate immediate-upload export requires a real callback; per-file progress, retry and abort belong to that adapter. It is currently used only by the isolated test fixture, not Recognition persistence.

[Recognition service](../../../apps/web/src/features/recognition/service.ts) posts metadata plus evidence parts together. Optional Axios progress measures transferred request bytes; unknown total is indeterminate,100% waits for response. Only confirmed success closes/invalidates. Errors retain text/files for explicit retry; resubmit still requires replacement evidence. Chooser cancellation preserves the draft; in-flight close remains busy-locked, with no new server-abort guarantee. [Private gallery/PDF capabilities](dialogs-and-media.md#recognition-depthcarousel-and-evidence-capability) remain separate from selection.
